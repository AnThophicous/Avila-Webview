# Browser Foundation

Avila is designed to support both `AppView` and `BrowserApp`. The browser API must not weaken the zero-trust bridge model.

## Current Implemented Layer

Avila exposes native WebView2 controls for the main local shell:

- `browser.navigate(url)`
- `browser.back()`
- `browser.forward()`
- `browser.reload()`
- `browser.stop()`
- `browser.canGoBack()`
- `browser.canGoForward()`
- `browser.setZoom(level)`
- `browser.find(text)`
- `browser.openDevTools()`
- events: `loading`, `loaded`, `title`, `url`, `error`

This gives Avila a real native navigation surface, but AppView and BrowserApp stay separate:

- `AppView` uses the local shell and `window.avila`
- `BrowserApp` opens a remote URL in a locked-down window and does not inject the SDK by default

## Remote WebViews

The runtime now supports separate remote WebView surfaces:

```txt
Avila local shell
  - trusted avila://local UI
  - receives window.avila
  - owns tabs, toolbar, permission UI, settings

Remote tab WebViews
  - no window.avila
  - isolated profiles/sessions
  - origin-scoped permissions
  - navigation/download/cookie events
```

The local shell should control remote views through native APIs, not by injecting privileged JavaScript into remote pages.

Implemented API:

```js
const view = await avila.webview.create({
  url: "https://example.com",
  bounds: { x: 220, y: 44, width: 1000, height: 700 }
});

await avila.webview.navigate(view.id, "https://example.com/docs");
await avila.webview.setZoom(view.id, 1.1);
const shot = await avila.webview.screenshot(view.id);
```

Remote WebViews emit `webview.loading`, `webview.loaded`, `webview.title`, `webview.url`, `webview.error`, `webview.crash`, and lifecycle events.

## Tabs

Implemented API:

```js
const tab = await avila.tabs.create({ url: "https://example.com", active: true });
await avila.tabs.activate(tab.id);
await avila.tabs.close(tab.id);
const tabs = await avila.tabs.list();
```

Native requirements:

- each tab has an ID generated by runtime
- tab WebViews are owned by native runtime
- remote tabs never receive the Avila bridge
- tab lifecycle emits events through the `webview.*` event channel
- inactive tabs can be hidden now and suspended later for memory control

## Sessions and Profiles

Target API:

```js
await avila.browser.createSession("default");
await avila.browser.clearData({ session: "default", cookies: true, cache: true });
```

Native requirements:

- separate WebView2 user data folders per profile
- profile names normalized and sandboxed
- data clearing is explicit and auditable
- no shared cookies between isolated sessions unless configured

## Cookies

Target API:

```js
await avila.cookies.get({ url: "https://example.com", name: "sid" });
await avila.cookies.set({ url, name, value, sameSite: "Lax", secure: true });
await avila.cookies.clear({ url });
```

Security requirements:

- origin is required
- values are never logged
- cookie APIs are disabled for remote pages
- access is scoped by manifest permission and origin allowlist

## Downloads

Target API:

```js
avila.downloads.onStart(download => {});
await avila.downloads.accept(download.id, { path: "downloads/file.zip" });
await avila.downloads.cancel(download.id);
```

Native requirements:

- downloads start paused by default when policy requires confirmation
- path must be selected by user or inside allowed download directory
- file name is sanitized
- dangerous extensions can require explicit confirmation
- download progress events are rate-limited

## Web Permissions

Browser mode must handle:

- camera
- microphone
- geolocation
- notifications
- clipboard from web pages
- MIDI/USB/Bluetooth later

Policy:

- deny by default
- prompt through local shell UI
- remember decisions only when configured
- separate decisions by origin and session

## TLS and Certificate Events

Target events:

- invalid certificate
- TLS error
- mixed content
- blocked insecure form

Policy:

- fail closed by default
- do not allow JavaScript to silently bypass TLS
- expose safe diagnostic text only
- require user or manifest policy for exceptions

## Request Interception

Target API:

```js
await avila.browser.interceptRequest({
  origins: ["https://example.com"],
  resourceTypes: ["image", "script"],
  action: "block"
});
```

Use cases:

- ad blocking
- custom headers
- local protocol mapping
- proxy rules
- privacy filters

Security requirements:

- no arbitrary header injection into protected headers
- no leaking Authorization/Cookie headers to JavaScript
- bounded response body size
- explicit origin scopes

## Performance Metrics

Target API:

```js
const metrics = await avila.browser.getMetrics();
```

Metrics should include:

- navigation start/end
- first contentful paint when available
- memory estimate
- resource count
- error count
- worker queue pressure
- tab suspension status

Never collect:

- page text
- credentials
- cookies
- form values
- private keys
